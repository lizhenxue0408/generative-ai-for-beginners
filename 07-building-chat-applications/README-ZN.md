### 聊天机器人还是聊天应用？

在深入构建聊天应用之前，让我们将“聊天机器人（chatbots）”与“AI 驱动的聊天应用（AI-powered chat applications）”进行比较，它们扮演不同的角色和功能。聊天机器人的主要目的是自动化特定的对话任务，例如回答常见问题或跟踪包裹。它通常由基于规则的逻辑或复杂的 AI 算法控制。相比之下，AI 驱动的聊天应用是一个宽泛得多的环境，旨在促进各种形式的数字通信，例如人类用户之间的文本、语音和视频聊天。其定义特征是集成了生成式 AI 模型，该模型模拟细致入微、类人的对话，基于各种各样的输入和上下文线索生成回复。一个生成式 AI 驱动的聊天应用可以参与开放领域的讨论，适应不断演变的对话上下文，甚至产生创造性或复杂的对话。

下表概述了关键差异和相似之处，以帮助我们理解它们在数字通信中的独特角色。

| 聊天机器人                               | 生成式 AI 驱动的聊天应用 |
| ------------------------------------- | -------------------------------------- |
| 以任务为中心且基于规则           | 上下文感知                          |
| 通常集成到更大的系统中  | 可能托管一个或多个聊天机器人      |
| 局限于已编程的功能       | 集成了生成式 AI 模型      |
| 专门化且结构化的交互 | 能够进行开放领域讨论     |

### 利用 SDK 和 API 的预构建功能

在构建聊天应用时，一个很好的第一步是评估已经存在的东西。使用 SDK 和 API 来构建聊天应用是一种有优势的策略，原因有很多。通过集成文档完善的 SDK 和 API，你正在为应用的长期成功进行战略定位，解决可扩展性和维护问题。

- **加快开发过程并减少开销**：依靠预构建的功能，而不是自己构建这些功能的昂贵过程，让你能够专注于应用中你可能认为更重要的其他方面，例如业务逻辑。
- **更好的性能**：当你从零开始构建功能时，你最终会问自己“它如何扩展？这个应用能否处理用户的突然涌入？”维护良好的 SDK 和 API 通常对这些担忧有内置的解决方案。
- **更轻松的维护**：当有更新和改进时，由于大多数 API 和 SDK 在发布新版本时只需要更新一个库，因此更容易管理。
- **获取前沿技术**：利用在广泛数据集上微调并训练过的模型，为你的应用提供自然语言处理能力。

访问 SDK 或 API 的功能通常涉及获取使用所提供服务的权限，这通常通过使用唯一密钥或身份验证令牌来实现。我们将使用 OpenAI Python 库来探索这看起来是什么样子。你也可以在本课的以下 [OpenAI notebook](./python/oai-assignment.ipynb?WT.mc_id=academic-105485-koreyst) 或 [Azure OpenAI Services notebook](./python/aoai-assignment.ipynb?WT.mc_id=academic-105485-koreys) 中自己尝试。

```python
import os
from openai import OpenAI

API_KEY = os.getenv("OPENAI_API_KEY","")

client = OpenAI(
    api_key=API_KEY
    )

response = client.responses.create(model="gpt-5-mini", input="Suggest two titles for an instructional lesson on chat applications for generative AI.", store=False)
print(response.output_text)
```

上面的示例使用了带 Responses API 的 GPT-5 mini 模型来完成提示，但请注意 API 密钥是在此之前设置的。如果你没有设置密钥，你会收到一个错误。

## 用户体验（UX）

一般的 UX 原则适用于聊天应用，但由于涉及的机器学习组件，这里有一些变得特别重要的额外考量。

- **解决歧义的机制**：生成式 AI 模型偶尔会生成含糊的答案。允许用户请求澄清的功能，在用户遇到此问题时可能会很有帮助。
- **上下文保持**：先进的生成式 AI 模型有能力在对话中记住上下文，这对用户体验来说可能是一项必要资产。让用户能够控制和管理上下文，可以改善用户体验，但也带来了保留敏感用户信息的风险。关于这些信息存储多长时间的考量，例如引入保留策略，可以平衡对上下文的需求与隐私。
- **个性化**：凭借学习和适应的能力，AI 模型为用户提供个性化的体验。通过用户资料等功能定制用户体验，不仅让用户感到被理解，还能帮助他们追求找到特定答案，创造更高效、更令人满意的互动。

### 无障碍

无论用户有视觉、听觉、运动或认知障碍，一个设计良好的聊天应用都应该可供所有人使用。以下列表分解了旨在增强各种用户障碍无障碍性的具体功能。

- **视觉障碍功能**：高对比度主题和可调整大小的文本、屏幕阅读器兼容性。
- **听觉障碍功能**：文本转语音和语音转文本功能、音频通知的视觉提示。
- **运动障碍功能**：键盘导航支持、语音命令。
- **认知障碍功能**：简化的语言选项。

## 领域特定语言模型的定制与微调

想象一个聊天应用，它能理解你公司的行话，并预见到其用户群通常有特定的查询。有几种方法值得一提：

- **利用 DSL 模型**。DSL 代表领域特定语言（domain specific language）。你可以利用一个在特定领域上训练过的所谓 DSL 模型来理解其概念和场景。
- **应用微调**。微调是用特定数据进一步训练你的模型的过程。

## 定制：使用 DSL

利用领域特定语言模型（DSL 模型）可以通过提供专门化、上下文相关的互动来增强用户参与度。它是一个经过训练或微调以理解和生成与特定领域、行业或主题相关文本的模型。使用 DSL 模型的选项从零开始训练，到通过 SDK 和 API 使用预训练的模型不等。另一种选择是微调，即采用现有的预训练模型并使其适应特定领域。

## 定制：应用微调

当预训练模型在专门领域或特定任务上表现不佳时，通常会考虑微调。

例如，医疗查询很复杂，需要大量上下文。当医疗专业人员诊断患者时，是基于多种因素，如生活方式或既往病史，甚至可能依赖最近的医学期刊来验证其诊断。在这种细微的场景中，通用的 AI 聊天应用无法成为可靠的来源。

### 场景：一个医疗应用

考虑一个旨在协助医疗从业者、提供治疗指南、药物相互作用或最新研究发现的快速参考的聊天应用。

一个通用模型可能足以回答基础医疗问题或提供一般性建议，但它可能在以下方面遇到困难：

- **高度特定或复杂的病例**。例如，神经科医生可能会问应用，“目前管理小儿患者耐药癫痫的最佳实践是什么？”
- **缺乏最新进展**。通用模型可能难以提供融合神经学和药理学最新进展的当前答案。

在这种情况下，用专门的医疗数据集对模型进行微调，可以显著提高其更准确、更可靠地处理这些复杂医疗查询的能力。这需要访问一个大型且相关的数据集，代表需要解决的领域特定挑战和疑问。

## 高质量 AI 驱动聊天体验的考量

本节概述了“高质量”聊天应用的标准，包括可操作指标的捕获，以及遵守一个负责任地利用 AI 技术的框架。

### 关键指标

为了保持应用的高质量性能，跟踪关键指标和考量至关重要。这些测量不仅确保应用的功能，还评估 AI 模型的质量和用户体验。以下是一个涵盖基本、AI 和用户体验指标的列表，供考量。

| 指标                        | 定义                                                                                                             | 对聊天开发者的考量                                                         |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| **正常运行时间（Uptime）**                    | 衡量应用可运行且用户可访问的时间。                                              | 你将如何最小化停机时间？                                           |
| **响应时间（Response Time）**             | 应用回复用户查询所花费的时间。                                                          | 你如何优化查询处理以改善响应时间？           |
| **精确率（Precision）**                 | 真正例预测占阳性预测总数的比例                                     | 你将如何验证模型的精确率？                        |
| **召回率（Recall，灵敏度）**      | 真正例预测占实际阳性总数的比例                                               | 你将如何测量并改进召回率？                                  |
| **F1 分数**                  | 精确率和召回率的调和平均数，平衡了两者之间的权衡。                                   | 你的目标 F1 分数是多少？你将如何平衡精确率和召回率？  |
| **困惑度（Perplexity）**                | 衡量模型预测的概率分布与实际数据分布的对齐程度。 | 你将如何最小化困惑度？                                         |
| **用户满意度指标** | 衡量用户对应用的感知。通常通过调查捕获。                                     | 你将多久收集一次用户反馈？你将如何据此适应？ |
| **错误率（Error Rate）**                | 模型在理解或输出中犯错的速率。                                                 | 你有哪些策略来降低错误率？               |
| **再训练周期（Retraining Cycles）**         | 模型更新以纳入新数据和洞见的频率。                                    | 你将多久重新训练一次模型？是什么触发了再训练周期？   |
| **异常检测（Anomaly Detection）**         | 用于识别不符合预期行为的异常模式的工具和技术。                        | 你将如何响应异常？                                        |

### 在聊天应用中实施负责任 AI 实践

微软的负责任 AI 方法确定了六项原则，这些原则应指导 AI 的开发和使用。以下是这些原则、它们的定义，以及聊天开发者应该考量、并认真对待它们的原因。

| 原则             | 微软的定义                                | 对聊天开发者的考量                                      | 为何重要                                                                     |
| ---------------------- | ----------------------------------------------------- | ---------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 公平性（Fairness）               | AI 系统应该公平对待所有人。            | 确保聊天应用不基于用户数据进行歧视。  | 在用户之间建立信任和包容性；避免法律后果。                |
| 可靠性与安全性（Reliability and Safety） | AI 系统应该可靠且安全地运行。        | 实施测试和故障安全机制以最小化错误和风险。         | 确保用户满意并防止潜在伤害。                                 |
| 隐私与安全（Privacy and Security）   | AI 系统应该安全并尊重隐私。      | 实施强加密和数据保护措施。              | 保护敏感用户数据并遵守隐私法律。                         |
| 包容性（Inclusiveness）          | AI 系统应该赋予每个人力量并让人参与。 | 设计对多样化受众可访问且易用的 UI/UX。 | 确保更广泛的人群能有效使用该应用。                   |
| 透明度（Transparency）           | AI 系统应该是可理解的。                  | 为 AI 回复提供清晰的文档和推理。            | 如果用户能理解决策如何做出，他们更可能信任一个系统。 |
| 问责制（Accountability）         | 人们应该对 AI 系统负责。          | 建立清晰的审计和改进 AI 决策的流程。     | 在出错时进行持续改进和纠正措施。               |
